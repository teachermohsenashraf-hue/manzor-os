# MANZOOR OS

مشروع مستقل في مجلد «منظور النظام التشغيلي». الواجهة تستخدم خط ثمانية الممدود Serif Display من الملفات المستضافة في صفحة ثمانية الرسمية، مع هوية منظور وشعارها وشريطها ونقطتيها الكهرمانيتين. الواجهة عربية RTL بالأبيض والأسود والكهرماني.

**الحالة:** يحتوي المشروع على شيفرة الفرق وCRM والإنتاج والطلبات والاشتراكات وأجزاء من المحرك المالي حتى المرحلة 5C. طُبقت 13 ترحيلًا ونجحت اختبارات تكامل محددة على PostgreSQL في مخطط معزول. راجع `IMPLEMENTATION_PROGRESS.md` للتفاصيل، ولا تستخدمه بوصفه نظامًا ماليًا جاهزًا للإنتاج

## معاينة الواجهة

```powershell
npm install
npm run db:generate
npm run dev
```

افتح http://localhost:3000/login. صفحة الدخول والخط والثيم يعملون دون قاعدة. الدخول وإدارة الحسابات يتطلبان PostgreSQL. لا يوجد حساب افتراضي أو وضع دخول تجريبي.

## الربط بـSupabase

1. انسخ `.env.example` إلى `.env` وضع رابط PostgreSQL من Connect في `DATABASE_URL` و`DIRECT_URL`. رابط المشروع الذي يبدأ بـ`https://` لا يصلح لاتصال Prisma. لا تضع كلمة المرور في المحادثة أو Git أو متغير NEXT_PUBLIC
2. `DATABASE_URL`: اتصال الخادم؛ للـNode المستمر استخدم session pooler عند الحاجة لـIPv4. للنشر serverless اختر إعداد الاتصال المناسب من لوحة Supabase. `DIRECT_URL`: اتصال direct/session لترحيلات Prisma. فعّل TLS وتحقق من شهادة الخادم، ولا تستخدم rejectUnauthorized=false.
3. اضبط `APP_ORIGIN` على أصل التطبيق الفعلي. محليًا `http://localhost:3000`؛ في الإنتاج عنوان HTTPS الكامل دون مسار.
4. شغّل `npm run db:migrate` بحساب الترحيل. استخدم دور تطبيق محدودًا في الإنتاج، وليس حساب postgres الإداري. قواعد RLS/حظر أدوار anon/authenticated في الترحيل تحمي الجداول من Data API؛ التطبيق يتصل بالخادم ولا يستخدم مفتاح anon لقراءة هذه الجداول.
5. أنشئ حساب المالك مرة واحدة في طرفية خاصة:

```powershell
$env:OWNER_NAME = 'اسم المالك'
$env:OWNER_USERNAME = 'owner-name'
npm run owner:create
```

يعرض الأمر كلمة مرور عشوائية مرة واحدة للمشغّل، ولا يحفظها في ملف. خزّنها بأمان؛ تغييرها مطلوب عند أول دخول. لا يطبع التطبيق أو سجل التدقيق كلمات المرور. لا تشغّل هذا الأمر في سجل CI عام.

6. شغّل `npm test` و`npm run test:integration` على مخطط الاختبار المعزول و`npm run build` ثم `npm start`. نفّذ اختبارات القيود والصلاحيات قبل أي استخدام فعلي

أمر `npm run test:integration` يستخدم `DIRECT_URL` من `.env` ويشغّل الاختبارات في مخطط `manzoor_test` داخل قاعدة Supabase نفسها. طبّق الترحيلات على هذا المخطط قبل أول تشغيل للاختبارات. تبقى بيانات التطبيق الفعلية في `public` ولا يكتب الاختبار فيها

## خط ثمانية في النسخة العامة

يحظر ترخيص ملفات الخط إعادة توزيعها كملفات مستقلة، لذلك تبقى ملفات `src/app/fonts/*.woff2` خارج GitHub. تستخدم الواجهة أوزان Regular وBold وBlack من الملفات المستضافة التي تستخدمها `font.thmanyah.com`، ولا يتطلب البناء تنزيل الخط محليًا. تسمح استجابات تلك الملفات بطلب الخط من النطاقات الأخرى. يعتمد عرض الخط عند المستخدم على استمرار إتاحتها من الجهة المستضيفة

## نشر Vercel

- استخدم إعداد Next.js الافتراضي وأمر البناء `npm run build` وNode.js 24
- ضع `DATABASE_URL` كرابط PostgreSQL في متغيرات بيئة Vercel السرية للنشر الفعلي، ولا تستخدم رابط مشروع Supabase الذي يبدأ بـ`https://`
- ضع `APP_ORIGIN` بعنوان النطاق الفعلي كاملًا مثل `https://your-domain.example` دون مسار أو شرطة أخيرة. يمنع فحص المصدر تسجيل الدخول إذا لم يطابق هذا العنوان
- لا يحتاج البناء إلى متغيرات قاعدة البيانات، لكن صفحات التطبيق وعمليات الدخول تحتاج `DATABASE_URL` عند التشغيل. استخدم `DIRECT_URL` للترحيلات من بيئة إدارية منفصلة، ولا تشغّل الترحيلات تلقائيًا في بناء Vercel
- لا ترفع `.env` أو ملفات الخط إلى GitHub. إذا فشل استيراد المشروع الأول في Vercel قبل إنشائه، أعد الاستيراد بعد ظهور الالتزام الجديد في `main`

## الملفات الأساسية

- PRODUCT_SPEC.md: النطاق والبنية ومراحل الإنجاز.
- BUSINESS_RULES.md: مصادر القواعد المؤكدة والقرارات المعلقة.
- STATUS.md: المنفذ وما بقي والتحقق الفعلي.
- IMPLEMENTATION_PROGRESS.md: تقدم المرحلة الثانية وما لم يختبر.
- prisma/schema.prisma: مخطط الأساس.
- src/app/actions.ts: عمليات الحسابات والتحقق الخادمي.
- src/app/fonts: ثمانية من الموقع الأصلي. يُحفظ المصدر خاصًا.

## التشغيل والأمان

جلسة 8 ساعات، cookie HttpOnly/SameSite/Secure في الإنتاج، تحقق Origin، إبطال الجلسات عند تغيير كلمة المرور أو الصلاحية، حد 8 محاولات دخول لكل اسم مستخدم خلال 15 دقيقة في قاعدة البيانات. الحسابات غير المالكة لا تملك صلاحيات إدارية أو مالية ضمن هذه المرحلة. حماية إضافية للحافة/IP ومراجعة الأداء مطلوبة قبل إطلاق عام.

يلزم فصل مستخدم الترحيلات عن التطبيق، واختبار النسخ الاحتياطية والاستعادة في Supabase على قاعدة منفصلة، وجدولة تنظيف الجلسات المنتهية وسجلات منع المحاولات بعد الربط. لا تُنشر هذه النسخة بوصفها نظامًا ماليًا جاهزًا.
